# analyze（`insn.rkt` `cfg.rkt` `analyze.rkt`）

## 作用

控制流分析：把线性 item 切成基本块，并给出每个块的后继、顺序下落和 root 标记。

## 相关 s-exp

| 输入 | 输出 |
| --- | --- |
| 扁平程序 item 列表 | `(struct program blocks flows)` |
| `data-items`（只用于找“地址被取过”的链） | `program` |
| `(label 链…)` / 控制转移 | 块边界、`succ`、`fallthrough` |
| 数据里的地址表达式 `(链)` / `(+ …)` / `(- …)` | root 标记 |

`block` 是 `(block <头链列表> item…)`。
`flow` 是 `(flow (succ id…) (fallthrough id|#f) (root? bool))`。

## 设计思路

- 块边界只由控制流决定：程序开头、跳转目标 label、`ends-block?` 指令之后。
- 非目标 label 只是块内位置标记，不切块。
- `succ` 服务可达性，`fallthrough` 服务物理布局；两者分开。
- 数据 item 不进 CFG，只贡献 root：数据里存地址 = 把入口交给外部。

## 可达性：哪些块算根（两个因子决定可靠性）

"这个块不可达"是一个对**本产物**的闭世界断言，删代码就是靠它。二进制层只
看得见自己的控制流，所以根集合必须把所有"从图外面进来"的入口都算上：

1. **地址被取过的块**（`(value …)` 里的链、指令里的裸链、内存 disp）。这些地址
   可能来自跳转表、IDT 门描述符、syscall MSR…… 也就是有人会从数据里跳进来。
   这里**恒保守**：不看镜像里有没有间接跳转指令。
   （曾经用一个全局布尔 `graph-indirect?` 做闸门，等于"用一条指令的存在与否决定
   整张图的可达性语义"；闸门关闭的那一侧是不保守的，同一个 IDT 描述符在两个
   镜像里命运相反。实测 pc-repl 15 万块恒保守的代价是 0 块 0 字节。）
2. **"会不会顺序落下"** 这个事实在 `amd64-asm/control-flow.rkt`（由
   `special/table.rkt` 逐 form 声明）：只有我们自己生成的转移形式
   （`jump` / `jump-indirect`）和硬件保证的 `ret`/`ud2`（`stop`）能声明
   "不落下"，其余——包括 `hlt` / `pause` / `mwait` / `syscall` / `sysretq`——
   一律按会落下处理。`analyze/insn.rkt` 只把它翻译成谓词，不保存事实。
   （判错"不落下"会删掉还在执行的代码，判错"落下"只多留几字节。）

看不见的东西（中断/异常返回、别的核、外部 loader 直接跳进某个物理地址、自修改
代码）没法从二进制里证明；它们正好都被第 1、2 条覆盖：要么地址在数据里出现，
要么就是普通的顺序落下。

## 边界

不改程序、不判指令合法性、不算尺寸/地址、不删块。
